# 毕业进度小管家服务器部署说明

## 一、计划正式地址（完成生产部署与 HTTPS 验证后生效）

- 前端：`https://biyejindu.jinshengxu.com.cn/`
- 运营后台：`https://biyejindu.jinshengxu.com.cn/credit-admin.html`
- Java 服务仅监听：`127.0.0.1:4180`
- 原简历网站继续监听：`127.0.0.1:4174`

## 二、域名解析

在阿里云云解析 DNS 中，为 `jinshengxu.com.cn` 增加记录：

| 配置项 | 值 |
|---|---|
| 记录类型 | A |
| 主机记录 | biyejindu |
| 记录值 | 当前轻量服务器的公网 IPv4 |
| TTL | 默认值即可 |

等待解析生效后，在本地执行 `nslookup biyejindu.jinshengxu.com.cn`，确认返回当前服务器公网 IPv4。不要删除或修改 `@`、`www` 等简历网站已有记录。

## 三、上传与执行

当前服务器更新包固定为：

```text
release/biyejindu-deploy-20261006-1830.zip
```

每次交付会原位重建同名 ZIP，因此不能凭文件名判断版本。必须在本机记录该次 SHA-256，上传后在服务器再次计算并比对。

1. 把整个部署压缩包上传到服务器，例如 `/home/admin/`。
2. 执行 `sha256sum biyejindu-deploy-20261006-1830.zip`，与本次交付值逐字符一致后再解压。
3. 解压后执行 `sha256sum -c SHA256SUMS.txt`，确认 WAR、脚本和说明文件均为 `OK`。
4. 首次安装执行：

```bash
sudo bash install-biyejindu.sh
```

脚本会执行以下操作：

- 核验简历网站服务和 `4174` 端口；
- 安装 Java 21，但不修改 Node.js；
- 在没有 Swap 时创建 2 GiB Swap；
- 下载 Apache Tomcat 9.0.122 并校验 SHA-512；
- 创建独立的 `biyejindu` 系统账号；
- 以 `700 MiB` 服务内存上限运行；
- 只监听本机 `4180` 端口；
- 添加独立 Nginx 配置；
- 为新子域名申请独立 HTTPS 证书；
- 保留原简历网站配置和服务；
- 在终端显示后台初始密码，并创建 DeepSeek 设置加密密钥；真实 DeepSeek API 密钥不会写入发布包。

## 四、部署后检查

```bash
systemctl status biyejindu --no-pager
systemctl status xjs-portfolio --no-pager
ss -lntp | grep -E '4174|4180|:80|:443'
curl -I https://biyejindu.jinshengxu.com.cn/
curl -I https://jinshengxu.com.cn/
```

预期结果：

- `biyejindu` 和 `xjs-portfolio` 都是 `active (running)`；
- `4174` 与 `4180` 均只绑定 `127.0.0.1`；
- 公网只开放原有的 80、443、22；
- 两个域名均可通过 HTTPS 访问。

再登录运营后台完成以下检查：

1. 配置 DeepSeek API 密钥、模型与推理档位，并执行“测试连接”。
2. 确认后台页面只显示“已配置”，不会回显完整 API 密钥。
3. 使用脱敏测试材料执行一次“解析并 AI 二次核对”，确认返回核对意见。
4. 修改课程板块或学分后点击“更新学分结果”，再修改一次并二次点击更新，核对总学分、百分比、板块明细、优先关注和核验清单全部变化一致。

## 五、回滚

如果新网站出现异常，进入解压后的部署目录执行：

```bash
sudo bash rollback-biyejindu.sh
```

该脚本只停止新网站并撤销新域名入口，不删除业务数据、不删除证书、不撤销 Swap，也不修改简历网站。

## 六、以后更新网站

以后更新不要重复运行首次安装脚本。把新的 `student_system.war` 与 `update-biyejindu.sh` 放在同一目录，然后执行：

```bash
sudo bash update-biyejindu.sh
```

更新脚本采用以下隔离措施：

| 项目 | 简历网站 | 毕业进度小管家 |
|---|---|---|
| 系统服务 | `xjs-portfolio.service` | `biyejindu.service` |
| 本机端口 | `127.0.0.1:4174` | `127.0.0.1:4180` |
| 程序目录 | `/opt/xjs-portfolio` | `/opt/biyejindu`、`/var/lib/biyejindu` |
| Nginx 配置 | 原配置保持不变 | `/etc/nginx/conf.d/biyejindu.conf` |
| 更新动作 | 不重启、不改文件 | 仅原子替换 WAR 并重启自身 |

更新前后都会检查简历服务和 `4174` 端口。新版本在 `4180` 的健康检查失败时，会自动恢复旧 WAR 并再次启动毕业进度服务。更新脚本不运行 `nginx reload`，不会修改证书，也不会安装或升级 Node.js、Java、Tomcat。

由于服务器只有约 `1.6 GiB` 内存，不建议在同一时刻再启动第二套 Java 蓝绿实例；双 Java 实例的内存压力反而更可能波及简历网站。当前方案会让毕业进度站点在自身重启时短暂不可用，但简历网站持续运行，是这台轻量服务器上风险更低的方案。

## 七、管理密钥

首次部署成功后，终端会输出后台初始密码。请立即保存到密码管理器，登录后可在后台修改。修改后的密码只保存单向哈希；环境中的初始密码仍可作为恢复凭据。服务器环境文件为：

```text
/etc/biyejindu/biyejindu.env
```

该文件权限为 `0640`，包含 `CREDIT_AUDIT_ADMIN_KEY`、`CREDIT_AUDIT_SETTINGS_KEY` 和可选的 `DEEPSEEK_API_KEY`。不要下载、公开或粘贴到聊天中。优先在后台录入 DeepSeek API 密钥，使其由 `CREDIT_AUDIT_SETTINGS_KEY` 加密保存；无论采用哪种方式，前端接口都不得返回完整密钥。

本地开发环境中使用 `123456` 只用于本机检查，不得作为生产密码。

## 八、证书自动续期与首次部署修复说明

首次生产部署在真实服务器上暴露并修复了以下问题，当前 `install-biyejindu.sh` 已把修复固化：

- Tomcat runtime 保持 `root` 所有，但组改为 `biyejindu`，目录和脚本只授予运行所需的最小读取/执行权限，避免 `203/EXEC`。
- 预创建 `$CATALINA_BASE/conf/Catalina/localhost`，只给该运行时子目录写权限，不放宽整个 `conf`。
- systemd 增加 `WorkingDirectory=/var/lib/biyejindu/tomcat`，确保相对日志路径写入 Tomcat Base 下的 `logs/`。
- `server.xml` 继续禁用 shutdown port，不再调用 `catalina.sh stop`；服务停止交给 systemd 的 OS 信号。
- HTTPS 配置不再假定 `/etc/letsencrypt/options-ssl-nginx.conf` 一定存在，直接使用证书路径与 `TLSv1.2 TLSv1.3`。
- Certbot 写入 deploy hook；续期成功后先检查 Nginx 配置，通过后才 reload。

生产服务器应执行一次模拟续期验证：

```bash
systemctl list-timers --all | grep -Ei 'certbot|letsencrypt' || true
grep -RniE 'deploy_hook|renew_hook' /etc/letsencrypt/renewal /etc/letsencrypt/renewal-hooks 2>/dev/null || true
certbot renew --dry-run --run-deploy-hooks
```

模拟续期成功的核心标志是出现类似 `Congratulations, all simulated renewals succeeded`，并且执行后：

```bash
nginx -t
curl -I https://biyejindu.jinshengxu.com.cn/
curl -I https://jinshengxu.com.cn/
```

两站仍应正常。若 Certbot 显示 `Hook 'deploy-hook' ran with error output`，先看 hook 的退出状态和后续结果；`nginx -t` 本身会把成功提示写到标准错误输出，因此仅出现“error output”字样不等于 hook 执行失败。
