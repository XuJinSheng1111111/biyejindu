## 二、网络资料交叉核对与项目借鉴

| 风险或建议 | 主要依据 | 项目中的处理方法 |
|---|---|---|
| 上传文件不应只信任扩展名 | OWASP 文件上传安全速查表 | 扩展名、真实格式、大小和允许类型共同校验 |
| 上传可能造成磁盘或内存拒绝服务 | OWASP 拒绝服务安全速查表 | 文件大小、请求大小、频率、并发、解析时间、内存和展开体积多层限制 |
| Office 压缩文件可能是 ZIP 炸弹 | Apache POI `ZipSecureFile` 文档 | 设置最小压缩比、最大条目大小和最大文本大小，并增加应用侧累计限制 |
| PDF 解析可能大量占用内存 | Apache PDFBox 内存使用说明 | 使用磁盘临时缓存，并限制文本长度和处理超时 |
| 跨站请求可诱导匿名上传或后台写入 | OWASP CSRF 防护速查表 | 同源校验、`Sec-Fetch-Site` 和脚本专用请求头联合判断 |
| CSV 内容可能被表格软件作为公式执行 | OWASP CSV 注入说明 | 对 `= + - @` 等危险开头进行安全转义 |
| 安全响应头应形成浏览器防护层 | OWASP HTTP 响应头速查表 | CSP、HSTS、`nosniff`、禁止框架嵌入和权限策略 |
| Tomcat 不应以 root 身份运行 | Apache Tomcat 9 安全指南 | 独立无登录用户、限制目录权限、只开放必需的写目录 |
| Tomcat 默认应用会增加攻击面 | Apache Tomcat 9 安全指南 | 独立 `CATALINA_BASE`，不部署 manager、host-manager、docs、examples |
| Tomcat 连接器应限制参数和上传部分数 | Apache Tomcat 9 连接器文档 | `maxParameterCount=40`、`maxPartCount=8`、请求大小限制；前台解析最多需要 7 个部分 |
| 反向代理必须限制请求体 | Nginx 官方核心模块文档 | `client_max_body_size 18m`，并设置请求体超时 |
| 依赖漏洞需要持续检查 | OWASP 易受攻击依赖管理与 SBOM 指南 | 固定依赖版本、生成依赖清单并在交付前执行漏洞查询 |
| 安全日志应保留但避免无限增长 | OWASP 日志记录安全速查表 | Tomcat 访问日志保留 14 天，应用日志滚动，Nginx 独立日志 |
| 外部 AI 数据应最小化 | OWASP 大语言模型应用安全与隐私最小化原则 | 不发送原文件和身份信息，只发送二次核对必要的脱敏学业数据 |

## 四、验证口径

- 自动化测试：38 项 Maven 测试和 8 项前端计算回归通过。
- 构建：`mvn package` 成功生成 WAR。
- 静态检查：前端 JavaScript 与三份部署脚本语法通过。
- 公开清单：真实材料、用户上传目录、私有配置、日志、截图、备份和构建物均被排除。
- 密钥扫描：公开清单未发现常见明文密钥格式；DeepSeek 只通过服务器环境或加密设置接入，仓库不保存真实 API 密钥。
- 依赖查询：使用 OSV（开放源代码漏洞数据库）批量接口检查 38 个运行时依赖；本次查询没有返回已知漏洞记录。该结果是查询时点快照，不替代后续持续更新与复查。
